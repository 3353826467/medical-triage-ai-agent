# 智能问诊 AI 客服系统 — 项目介绍与技术栈

> 面向医疗行业的智能问诊与客服系统，提供**症状咨询、智能分诊、报告解读、常见问题解答**四类核心能力。

---

## 一、项目简介

### 1.1 它解决什么问题

患者在就医前普遍面临三类信息不对称：

| 痛点 | 表现 | 本系统的处理 |
|---|---|---|
| **不知道挂什么科** | 同一症状可能跨越多个科室，患者凭经验挂号，挂错率高 | 智能分诊输出「首诊科室 + 紧急程度 + 可能情况 + 可执行建议」 |
| **看不懂检查报告** | 检验单上满屏箭头与英文缩写，缺乏解释 | 报告解读把指标翻译成大白话，逐项标注偏高/偏低及常见含义 |
| **就医流程问题反复问** | 挂号、医保、检查前准备、票据、转诊占客服大量重复工作量 | 就医服务 FAQ 基于知识库检索自动应答 |

同时，医疗场景对**安全性**的要求远高于普通客服：系统必须能在用户描述危急症状时第一时间给出就医/急救指引，而不是自由发挥。

### 1.2 定位

本系统定位为**就医前的信息咨询与分诊辅助工具**，输出健康参考信息，**不构成医疗诊断**，不能替代执业医师的面诊、检查与诊断。系统内置免责声明，且默认关闭具体用药剂量建议（`ALLOW_MEDICATION_ADVICE=False`）。

## 二、核心功能

| 能力 | 说明 | API 入口 |
|---|---|---|
| 🩺 **症状咨询** | 症状成因科普、居家护理要点、"什么情况必须去医院"的警示信号 | `POST /api/v1/chat` |
| 🚦 **智能分诊** | 推荐首诊科室 + 紧急程度分级 + 可能情况（含概率与依据）+ 可执行建议 | `POST /api/v1/triage` |
| 📄 **报告解读** | 检验 / 影像 / 病理报告翻译成大白话，逐项标注异常；支持 txt/md/docx/pdf 上传 | `POST /api/v1/report/interpret`<br>`POST /api/v1/report/upload` |
| 🏥 **就医服务 FAQ** | 挂号、医保、缴费、检查准备、票据、转诊等 | `GET /api/v1/faq` |

**其他特性**

- **多轮会话**：带患者画像（年龄 / 性别 / 病程 / 既往史 / 过敏史），上下文参与分诊
- **医疗安全护栏**：命中红旗症状时跳过模型，直接返回急诊指引（详见 §五）
- **RAG 检索增强**：答案附带"参考依据"（来源 + 相关度分数），可溯源
- **SSE 流式输出**：打字机效果，降低长回答的等待感
- **全链路降级**：没有 OpenAI Key、没有 Milvus 也能完整启动并给出合理答复

## 三、技术栈

### 3.1 总览

| 层 | 选型 | 说明 |
|---|---|---|
| **前端** | Vue 3.5（`<script setup>`）+ Vite 5.4 + marked 12 | 组合式 API，无 UI 框架依赖，样式手写 CSS 变量主题 |
| **后端** | FastAPI 0.143 + Pydantic v2.14 + Uvicorn 0.54 | 全异步，自带 OpenAPI/Swagger 文档 |
| **LLM 编排** | LangChain 1.4 / langchain-core 1.6 / langchain-openai 1.7 | `ChatOpenAI` + `ChatPromptTemplate` + Runnable 链 |
| **大模型** | 任意 **OpenAI 兼容**端点 | OpenAI / DeepSeek / 通义千问 / 智谱 / Moonshot / vLLM / Ollama |
| **向量库** | **Milvus 2.x**（pymilvus 3.0） | 生产环境；不可用时自动降级 |
| **降级检索** | 本地 JSON 索引 + 哈希向量 | 纯 Python 实现，零外部依赖 |
| **结构化输出** | JSON mode（`response_format=json_object`） | 失败自动回退正则提取，再失败回退规则引擎 |
| **运行时** | Python 3.14（venv 隔离） | 依赖见 `backend/requirements.txt` |

### 3.3 为什么这样选型

| 选择 | 理由 |
|---|---|
| **OpenAI 兼容协议**而非绑定单一厂商 | 换模型只改 `OPENAI_BASE_URL` + `LLM_MODEL` 两行；国内模型、私有化 vLLM/Ollama 都能直接接 |
| **Milvus** 做生产向量库 | 医疗知识库规模会持续增长，需要分布式、可持久化、支持亿级向量的方案 |
| **同时保留本地降级** | 演示、离线环境、CI 压测不能依赖外部服务；降级路径也保证了 Key 失效时服务不整体不可用 |
| **LangChain** 而非裸调 API | 提示词模板化、Runnable 链可组合、未来接 Agent/Tool 无需重写 |
| **Vue 3 + Vite 而非 React** | 单页聊天应用，组合式 API 心智负担低；Vite 冷启动快，构建产物小 |
| **SSE 而非 WebSocket** | 问诊是单向流式生成，SSE 更轻、可穿透代理、自动重连；前端用 fetch + ReadableStream 手解（`EventSource` 不支持 POST） |

## 四、RAG 检索设计

医疗问答最怕"模型编造"，因此所有回答都基于内置知识库检索。

```
markdown 语料 (data/knowledge/)
    │  6 个主题文件：常见症状 / 检验报告 / 影像报告 /
    │  就医服务 FAQ / 慢病管理 / 用药安全
    ▼
切分（CHUNK_SIZE=500，OVERLAP=60）
    ▼
Embedding
    ├─ 有 Key  → OpenAI 兼容 /embeddings（1536 维）
    └─ 无 Key  → 本地哈希向量（384 维）
                 uni/bi-gram 哈希 + 子线性 TF + 平滑 IDF + L2 归一化
                 额外保留英文原串（提升 LDL-C、HbA1c 等指标名区分度）
    ▼
向量库
    ├─ Milvus 可用 → collection: medical_kb
    └─ 不可用      → data/index/*.json 本地索引
    ▼
检索（TOP_K=4）+ 关键词混合重排（ENABLE_HYBRID_RERANK）
    ▼
答案附「参考依据」：标题 + 来源 + 相关度
```

**当前状态**：内置知识库 68 个切片，6 大主题。

## 五、医疗安全护栏（本项目的重点设计）

护栏是系统中**优先级最高**的模块，位于 `backend/app/safety/guard.py`，覆盖 **10 类红旗症状**：

| key | 场景 |
|---|---|
| `acs` | 急性冠脉综合征（胸痛、压榨感、放射痛） |
| `stroke` | 卒中 FAST（偏瘫、口角歪斜、言语含糊） |
| `respiratory` | 呼吸窘迫、严重哮喘 |
| `consciousness` | 意识障碍、抽搐 |
| `bleeding` | 大出血、咯血、黑便 |
| `pregnancy` | 妊娠急症 |
| `child_fever` | 婴幼儿高热惊厥 |
| `mental` | 心理危机、自杀倾向 |
| `anaphylaxis` | 过敏性休克 |
| `acute_abdomen` | 急腹症 |

处理顺序：

1. **红旗扫描**：对用户侧文本做规则匹配
2. **命中** → 直接返回 `urgency=emergency` 的急诊指引，**不调用大模型**（避免模型在危急场景下自由发挥带来风险）
3. **未命中** → 正常走「意图路由 → RAG → 能力链路」

护栏下沉在各能力链路的 `arun()` 入口，**任何 API 入口（含直连 `/api/v1/triage`）都无法绕过**。

紧急程度分级：`emergency`（立即 120）→ `urgent`（24h 内）→ `routine`（门诊择期）→ `self_care`（居家观察）。

## 七、运行方式

```bash
# 方式 A：Windows 一键启动
start-dev.bat          # 自动建 venv、装依赖、分别弹出前后端窗口

# 方式 B：手动
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
cd backend && ../.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000
cd frontend && npm install --registry=https://registry.npmmirror.com && npm run dev
```

| 地址 | 内容 |
|---|---|
| http://127.0.0.1:5173 | 问诊界面 |
| http://127.0.0.1:8000/docs | Swagger API 文档 |
| http://127.0.0.1:8000/api/v1/runtime | 引擎自检（当前是否降级） |

**接真实大模型**：

```bash
cp backend/.env.example backend/.env
# 填 OPENAI_API_KEY；换国内模型：
# OPENAI_BASE_URL=https://api.deepseek.com/v1
# LLM_MODEL=deepseek-chat
```

**接 Milvus**：`docker compose -f docker/docker-compose.milvus.yml up -d`（连不上会自动降级，不会导致启动失败）。

## 九、二次开发与演进方向

**已预留的扩展点**

- 加知识：往 `data/knowledge/` 丢 markdown（带 `category` / `source` front-matter）→ 调 `/api/v1/knowledge/ingest?rebuild=true`
- 加分诊规则：编辑 `backend/app/chains/rules.py` 的 `RULES`，新增 `TriageRule`
- 换模型：只改 `.env` 两行

**后续可演进方向**

1. **多模态报告**：接入 OCR / 视觉模型，直接识别报告图片
2. **Agent 化**：LangChain Tool Calling 对接院内 HIS 排班、号源、检查预约接口
3. **持久化**：会话从内存迁到 Redis / PostgreSQL，支持多副本部署
4. **可观测性**：链路 tracing（LangSmith / OpenTelemetry）、回答质量人工反馈闭环
5. **合规加固**：数据加密传输与存储、访问控制与审计日志、个人信息脱敏（`utils/text.py: mask_sensitive`）
6. **科室校准**：当前规则表覆盖 16 个科室的常见主诉，真实上线前需按目标医院的实际科室设置校准

## 十、合规提示

- 本系统定位为**就医前信息咨询与分诊辅助**，不得用于替代医生诊断或开具处方。
- `ALLOW_MEDICATION_ADVICE` 默认关闭，避免输出具体用药剂量建议。
- 内置知识库内容为通用医学常识，**不构成院内诊疗规范**，上线前应替换为经院内审核的版本。
- 生产环境接入真实患者信息时，需额外满足医疗数据合规留存、加密与审计要求。
